# design-system.md — NPB 網站及網頁簡報視覺與操作規範（定稿候選 v0.4）

> 核心：**暖色系、低刺激、專業的運動數據編排**。所有文字、圖表與控制項應能清楚閱讀，不使用真實人物照片、球團 Logo、球場照片或任何外部圖片素材。

## 1. 版面設計目標

1. 簡報必須比原始 Wiki 文章更容易掌握重點，不只是把長篇文字放在米色背景上。
2. 運用標題、段落密度、版面留白、資料卡、對照、時間軸、統計圖表建立閱讀順序。
3. 各場共用相同的視覺元件與操作模式；依內容挑選版型、拆頁，不隨意更換整套設計。
4. 以桌面閱讀為主要場景，同時確保手機不會因固定 16:9 版面而出現極小字或無法操作的控制項。
5. 不以顏色作為唯一辨識方式；球員評級一定同時顯示字母及必要說明。

## 2. 全站候選色票

| 用途 | 候選色碼 | 原則 |
|---|---|---|
| 背景 | `#F5F0E8` | 柔和暖米白 |
| 卡片背景 | `#FFFDF9` | 淡暖白 |
| 次要區塊 | `#E9E0D4` | 暖灰米色 |
| 主文字 | `#382F2B` | 深棕色，保留可讀性 |
| 次要文字 | `#655B54` | 柔和深棕灰 |
| 一般重點 | `#995D49` | 低飽和磚紅 |
| 輔助資訊 | `#596452` | 加深後的柔和灰橄欖綠，兼顧可讀性 |
| 分隔線 | `#D7CCBF` | 低刺激暖灰 |

上述為目前已討論的候選色碼；**正式色票驗收後才鎖定精確色碼**，AI 不得任意變更整體色彩方向。

- 使用低飽和度、低刺眼程度；但**文字與背景不可故意低到難以辨識**。
- 以 WCAG AA 作一般閱讀設計目標：一般文字對比至少 `4.5:1`；大字至少 `3:1`；必要 UI 圖形與狀態至少 `3:1`（依實際適用情況檢核）。
- 對比度應以實際文字、描邊、背景及顯示狀態測試，不以主觀「感覺清楚」代替。
- 不單靠紅綠對比表示不同球隊或高低評價；提供文字、數字、圖例、線型或位置等第二種辨識方式。
- **色彩搭配限制**：`#596452` 輔助文字置於暖米白 `#F5F0E8` 約 `5.49:1`，置於次要米色 `#E9E0D4` 約 `4.77:1`。磚紅 `#995D49` 置於暖米白約 `4.61:1`，但置於次要米色僅約 `4.00:1`；後者**不得用於一般尺寸的小字或次要文字**。遇此背景改用 `#382F2B`、`#655B54` 或 `#596452` 等經檢測合格的文字色，或調整背景（不擅改已指定的評級徽章色）。對比數字為純色色碼計算值，仍須在瀏覽器檢查實際狀態。

## 3. 球員評級徽章（專屬例外規範）

### 3.1 評級與形狀

- 使用**正圓形**，寬與高相等；不得改為方形、橢圓形或整張卡片填色。
- **正式評級僅 S、A、B、C、D、E**，依 `rules/npb-analysis.md` 定義，不使用 F、G。
- A～E：相同**中性灰色底**，字母使用各等級的指定顏色。
- S：**金色底＋白色 S 字母**，可以配適度深色描邊，禁止使用刺眼發光效果。
- `+`、`-` 與主字母採相同色系，字級可略小；不改變原始評價定義。

### 3.2 參考遊戲截圖的候選色碼

> 字母與 S 金底為使用者指定的**近似參考色碼**，不宣稱為遊戲官方色碼；A～E 中性灰底則已獲准依可讀性重新調整。色彩計算只檢查 RGB 對比，實際渲染仍須驗收。

| 等級 | 底色 | 字母色 | 識別 |
|---|---|---|---|
| S | `#BBA15A`（候選金色） | `#FFFFFF` | 白字／金底 |
| A | `#393432`（深暖灰；新版） | `#E7A5BF` | 粉紅 |
| B | `#393432` | `#E18C8C` | 珊瑚紅 |
| C | `#393432` | `#F2B567` | 橘色 |
| D | `#393432` | `#F2DA70` | 黃色 |
| E | `#393432` | `#C9D67E` | 黃綠 |

- **唯一調整的指定色碼是 A～E 灰底**：由 v0.1 的 `#77716C` 改成 `#393432`。S 金底 `#BBA15A` 與白字 `#FFFFFF`，以及 A～E 全部字母色均保留原值，不因對比測試自行變更。
- 依 WCAG 相對亮度公式計算，新灰底與原指定 A～E 字色的對比依序約 **6.15、4.87、6.77、8.79、7.83:1**，均達一般文字 4.5:1 的數值門檻；此為色碼理論值，仍須檢查實際渲染字形、尺寸與狀態。
- **S 白字與固定金底約 2.51:1**，不足以直接宣稱符合一般文字或大字的 WCAG AA 對比要求。保留指定顏色，採適當深色細描邊（或等效文字輪廓）、充足的字級及徽章外的清楚文字標籤改善辨識；仍需人工檢查，不得僅因加了描邊就自動宣稱通過。若仍有差異，誠實註記為使用者指定例外。
- 字母 `+`／`-` 必須與主字母同色、足夠大且可辨認，顏色不作為唯一語意線索；一般情形不得擅自換成另一組彩色文字。
- 如果指定色彩在實際渲染後仍無法達到適用的對比要求，**回報衝突並請使用者確認替代方案**，不可默默更改指定顏色或宣稱已通過無障礙驗收。
- 徽章須有可理解的文字替代資訊，如 `aria-label="單場評級 A 減"`；色覺差異、灰階與放大後都必須能識別。
- 視覺參照僅取**配色概念**，不複製原遊戲 UI 圖片或素材。

## 4. 中、英、日文字型（強制）

| 內容 | 優先指定字型 |
|---|---|
| 正體中文 | `DFKai-SB`（標楷體） |
| 英文及拉丁字母 | `Times New Roman` |
| 阿拉伯數字 | `Times New Roman` |
| 一般符號／標點 | `Times New Roman`（該字型不支援者使用可閱讀備援） |
| **日文漢字、平假名、片假名與日文標點** | **`UD Digi Kyokasho N-R`（UD Digi Kyokasho 系列）** |

### 4.1 多語混排規則

- 中文片段標註 `lang="zh-TW"`，日文原文／姓名片段標註 `lang="ja"` 或 `lang="ja-JP"`。資料中的 `name_lang`、`name_segments`、`text_segments` 與 `AGENTS.md` 第 3.4、3.5 節一致；前端必須依標記分段輸出語言語意與字型，不得忽略這些欄位。
- 不以「漢字 Unicode 區段」推斷中文或日文，因為中日共用許多漢字但字形不同。
- 為英文、阿拉伯數字及一般符號提供專用字型樣式或標記，讓它們在中文及日文段落中仍顯示 Times New Roman；保留日文標點使用日文字型。
- **日文正式姓名照原始資料完整保留**：不得將平假名／片假名強迫改漢字，不改日文特有字形或姓名異體字，不自行執行 NFKC 等可能更動姓名的字元正規化。
- 若 Wiki 只提供中文譯寫／名稱寫法而沒有可信日文正式寫法，不自行編造假名；將此列為待核對事項。
- 優先依本機已安裝字型顯示；缺少主要字型時，依序採日文字型 `Yu Mincho`、`serif` 等適當備援並記錄差異。備援無法保證完整符合指定視覺，驗收須註明。
- **主要驗收環境**：Windows 的 Chrome；以實際顯示、瀏覽器字型檢查與測試字串共同確認指定字型是否真正生效，不能只看 CSS 宣告值。測試正體中文、日文漢字與異體字、平假名、片假名、英文、數字、中日英混排及 `+/-` 評級；記錄測試裝置、作業系統、瀏覽器與字型缺失情況。
- **跨裝置備援**：手機或未安裝指定字型的裝置，須保留文字內容、語言標記及正確的日文字形顯示，不得自動改字或以「套用備援」冒充完全符合原指定字型。
- 不複製、嵌入或上傳未取得再散布授權的 Windows 字型檔至 GitHub。

## 5. 首頁排版

- 主標題橫幅位於**頁面水平置中且偏上方**，顯示網站標題與簡短副標。
- 下方依序排列**賽事圖塊／卡片**。每張卡片至少包含：日期、對戰球隊、比分與賽事類型。
- **整張卡片均可點擊**進入對應 HTML 簡報，並提供可見的鍵盤焦點狀態。
- 桌面採約 2～3 欄的響應式卡片網格，手機改單欄；不使用照片縮圖或隊徽。
- 由 `docs/data/games.json` 提供卡片資訊，新增賽事不必大幅修改首頁程式。

## 6. 簡報版面與控制項

### 6.1 版型

- 桌面主視覺以 **16:9 簡報比例**編排；窄螢幕採適合閱讀的響應式版型，不得強制縮小至小字。
- 依 `AGENTS.md` 第 3.2 節及 `wiki-to-slides.md` 第 5.1 節選用固定八種版型：`match-overview`、`roster-overview`、`game-timeline`、`key-play`、`player-analysis`、`comparison`、`summary`、`sources`。不得讓視覺層自行發明新 `layout` 名稱。
- 標題清楚、內文留白合理，資訊不夠放時**拆頁**，不要大量縮小字體。
- **八種版型的共用視覺契約**：同一套標題層級、文字尺寸階層、間距尺度、頁面邊界、色彩變數、圓形評級徽章與可辨識的圖表標示。版型可改變資訊排列方式，但不得變成風格各異的八套網頁。
- **響應式與縮放**：在窄螢幕及瀏覽器縮放到 `200%` 時，所有文字、重要資料、操作鈕與焦點仍須可閱讀、可到達；容許必要的垂直捲動或改為單欄，不能靠固定高度、溢出隱藏或單純縮小字體裁切內容。
- 所有資料圖表的顏色、圖例、標籤保持一致，不能將視覺效果當成資料證據。

### 6.1.1 標準版型的共用呈現規則

| `layout` | 視覺結構 | 必須防止的問題 |
|---|---|---|
| `match-overview` | 大比分、對戰、基本紀錄與賽事資訊 | 只用顏色暗示勝負、隊伍標籤不清 |
| `roster-overview` | 多欄／分頁球員清單與正圓形評級徽章 | 因擠版漏列替補、角色或面向評級 |
| `game-timeline` | 局數節點、比分變動、事件卡 | 無數據支持卻畫出精確比分曲線 |
| `key-play` | 主事件、已知事實、分析解釋與限制 | 用球場示意圖暗示未知球路／落點 |
| `player-analysis` | 球員姓名、清冊評級、數據與重點分析 | 畫面評級與清冊資料不同 |
| `comparison` | 同單位並排、分項標籤、差異說明 | 不同指標或單場與長期數據混比 |
| `summary` | 分層結論卡與後續觀察 | 結論與文章限定語氣分離 |
| `sources` | 來源名稱、已確認 URL、限制 | 把缺失的原始連結補成虛構 URL |

- `roster-overview` 的顯示資料**只能由** `slides.json.roster` 配合 `roster_player_ids` 取得；`player-analysis` 的姓名、語言與評級也從同一清冊讀取，避免重複資料矛盾。
- 共用渲染器依 `blocks.type` 使用適當 HTML 元素與圖表組件；所有文章字串使用安全文字節點或等效逸出處理，不能當 HTML 注入。
- 文字與日文姓名依 `name_lang`、`name_segments`、`text_segments`、`title_segments` 分段輸出；投影片標題中的姓氏亦須以清冊 `player_id` 明確分流，勿單靠完整姓名比對；包含英文字母、阿拉伯數字與拉丁符號的片段套用 Times New Roman。**只允許以字元類別辨識拉丁／數字，不可據此猜測漢字語言**。
- 圖表除顏色外必須有明確系列名稱、刻度／數值標籤與可閱讀的文字說明；來源資料與事件時序按 `AGENTS.md` 第 3.5 節驗證。

### 6.2 操作方式（極簡，位置固定）

- **左上角**：單一左箭頭「返回首頁」。不以工具列取代。
- **下方正中央**：並排相鄰的「上一頁」（左箭頭）與「下一頁」（右箭頭），減少滑鼠移動。
- 翻頁按鈕**上方**顯示 `目前頁 / 全部頁數`。
- **操作目標大小**：返回、上一頁及下一頁的實際可點擊區域均至少 `44 × 44 CSS px`，視覺仍只需極簡箭頭；相鄰控制項須有足夠間距避免誤觸。
- **手機安全區域**：底部置中的翻頁控制須考慮安全區域（可用 `env(safe-area-inset-bottom)`），避免被瀏覽器工具列、瀏海或頁面內容遮擋；必要時為正文保留控制項空間，不得讓內容被固定控制列蓋住。
- 首頁無須顯示翻頁按鈕；簡報首／末頁的相應按鈕須正確停用，而非連到不存在的頁面。
- 支援鍵盤左右方向鍵翻頁；不加入必要性不明的全螢幕、自動播放、縮圖面板或華麗轉場。
- 視覺僅呈現箭頭，按鈕應提供 `aria-label`／鍵盤焦點與足夠點擊範圍。箭頭可透過 CSS 線條或自行製作的 SVG 路徑，**不是外部圖片**。
- 進入新投影片時，避免讀屏器失去導覽線索；必要時讓頁碼／頁標題可被輔助科技得知。
- **鍵盤焦點**：`Tab`／`Shift+Tab` 可以到達可操作元素，焦點有明顯外框或等效提示；第一頁／末頁的停用狀態不應誤觸翻頁，也不得只用降低顏色對比表達不可用。

## 7. 不使用實際圖片

**全面禁止**：球員肖像、球團隊徽、球場／賽事照片、新聞圖片、截圖、網路下載圖片、AI 生成的仿真球員圖、第三方背景照片。

**允許**：以原生程式產生的長條、折線、時間軸、資訊卡、表格、線段、幾何裝飾及必要功能箭頭；這些僅可傳達確有資料依據的資訊。

網站載入不應需要外部影像 URL；專案不應包含圖片素材庫。必要程式圖形須避免誤導為真實的球場定位、球路與選手動作。

## 8. 版面與無障礙驗收

1. 所有文字的字型與 `lang` 標示符合規範，包含 `name_lang`、`name_segments`、`text_segments`；測試中文、英文、日文漢字、平假名、片假名、異體字及中日英混排，且不自動將日文姓名改寫成漢字。
2. 指定字型缺失時，有明確備援與測試註記；不得聲稱所有裝置必然完全相同。
3. 正圓 S～E 徽章符合底色與字色要求；字母、`+/-` 可在彩色／灰階與放大情況辨識。
4. 一般文字及控制項依適用的 WCAG 對比標準檢查；專屬評級配色若有衝突，報告而非掩飾。
5. 首頁橫幅偏上置中、卡片可點；不包含任何照片或外部圖像。
6. 返回箭頭左上、翻頁箭頭在畫面下方中央相鄰、頁碼正確；鍵盤與滑鼠均可用。
7. 至少在 Windows Chrome（主要環境）與狹窄手機視窗檢查文字溢出、卡片遮擋、按鈕位置、焦點狀態、八種共用版型與六種資料區塊的呈現；八種版型應檢查共用色票、字級、間距、頁面邊界、徽章與圖表圖例是否一致。
8. 在瀏覽器 `200%` 縮放下重新測試，**不得裁切內容或使重要操作無法觸及**；手機版可改排或捲動。返回與翻頁按鈕的點擊範圍至少 `44 × 44 CSS px`，並檢查底部安全區域與內容避讓。
9. 測試鍵盤 `Tab`／`Shift+Tab` 焦點、左右方向鍵翻頁、首末頁停用、頁碼及返回；檢查灰階下的評級徽章、球隊辨識及圖表標示，若有適當工具可補做色覺模擬。不能僅用顏色傳達資訊。
10. 逐項記錄字型實際渲染與備援情況、文字／UI 對比、灰階辨識、縮放及跨裝置測試結果（通過／未通過／未執行）；未實測不可宣稱通過。

### v1.2 顯示補充：逐局得分表

- 逐局得分使用原生語意化 HTML 表格，而非長條圖；1～9 局及合計皆需顯示，`X` 表示主隊未進攻並有文字註解。
- 對應表格共用既有暖色變數、標楷體（中文隊名）及 Times New Roman（局數／分數）；小螢幕僅讓表格區域水平捲動，不得裁掉內容。
- 不改變既有 S～E 徽章顏色、八種版型或底部翻頁元件。
